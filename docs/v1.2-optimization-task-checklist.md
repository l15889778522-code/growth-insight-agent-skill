## 1. 审查结论

v1.1 已经具备可运行的动态路由、阶段状态机、指标修订、人工确认、只读 SQL、结果文件、图表、指标血缘、Review 回退和断点恢复，不再是只有提示词的原型。

当前最需要加强的不是继续增加角色，而是让项目的三个核心卖点真正闭环：

1. **确认可信**：能区分“用户在 Codex 中确认”与“调用方把一段文字写进 CLI”。
2. **Agent 可证明**：能证明阶段结果来自指定原生子 Agent，并绑定原始响应和实际配置。
3. **证据可定位**：不只确认文件存在，还能定位到字段、行、JSON Pointer 或计算过程。

在这三项之外，查询执行竞态、历史产物覆盖、最终报告门禁和真实 MySQL 验证属于 v1.2 发布前必须修复的问题。模型分配、更多数据库、运行看板等能力应排在正确性之后。

## 3. 优先级与发布门槛

| 级别 | 定义 | 发布处理 |
|---|---|---|
| `P1` | 会破坏确认、来源、证据、执行一致性或完成状态的核心问题 | v1.2 发布前必须完成 |
| `P2` | 会影响可靠性、数据质量、可移植性或维护成本的问题 | 原则上纳入 v1.2；不能完成时必须明确降级边界 |
| `P3` | 体验、效率和后续扩展问题 | 可进入 v1.2.x 或后续版本 |

任务状态仅使用 `TODO`、`IN_PROGRESS`、`BLOCKED`、`DONE`。只有代码、测试、文档和验收证据同时完成，任务才能标记为 `DONE`。

## 5. 详细任务

### TRUST-001 用户确认来源与可信等级

当前 `runctl.py approve` 会校验审批对象、哈希、修订号和幂等键，但 `user_text` 由 CLI 调用方直接传入，无法证明文字来自 Codex 用户消息。

- [x] 调研当前 Codex 运行时是否提供可持久化的任务 ID、消息 ID、作者角色或主机签发回执。
- [x] 在审批 Schema 中加入 `source_surface`、`source_message_id`、`source_message_sha256`、`captured_at` 和 `trust_level`。
- [x] 若主机回执可用，审批必须绑定回执；若不可用，明确标记为 `self_asserted`，不得文档宣称为加密可信身份。
- [x] 拒绝复用旧消息、错误任务消息、错误产物哈希和伪造可信等级。
- [x] 保留现有幂等语义，并增加升级兼容测试。

验收：审计输出能明确回答“谁在什么任务中确认了哪个版本”，并诚实区分主机可信与调用方自报。

### TRUST-002 原生子 Agent 执行回执

当前 `thread_id`、模型和 Token 都可为空，`record-stage` 不要求先调用 `record-agent-runtime`；`raw-response.txt` 也没有注册或绑定到阶段产物。因此主任务自行构造 JSON 仍可能通过状态机。

- [x] 新增 `agent-execution-receipt.schema.json`。
- [x] 回执绑定 `run_id`、`stage_id`、attempt、角色、Agent 配置哈希、原始响应路径与哈希、线程或任务 ID、开始和完成时间。
- [x] `record-stage` 必须验证当前 attempt 的回执和 `raw-response.txt`，再接受解析后的 JSON。
- [x] 当前 1.2 run 必须拒绝结构上合法但版本为 1.1 的 Agent 响应；旧合同仅允许显式迁移或只读审计。
- [x] 修复 attempt 必须拥有独立回执，不能覆盖首次响应。
- [x] 模型和 Token 仍允许为 `null`，但缺失原因必须可区分为“运行时未提供”而不是“未记录”。

验收：没有当前角色执行回执，或原始响应、角色配置、stage JSON 任一被替换时，阶段均不能进入待确认状态。

### EVID-001 结构化证据引用与解析器

当前证据检查只验证路径存在，或字符串以已批准的 `stage_id:` 开头；`stage_id:anything` 和不存在的文件片段仍可能通过。

- [x] 将自由文本 `evidence_refs` 升级为结构化引用，至少包含 artifact ID、SHA-256、选择器类型和选择器值。
- [x] 支持 CSV 行/列、JSON Pointer、阶段字段、查询清单字段和已注册计算 ID。
- [x] 为计算结果增加输入证据、公式或表达式、输出值和精度元数据。
- [x] 实现统一 resolver，并由 Insight、Review、Report、血缘和 finalize 共用。
- [x] 为旧 v1.1 字符串引用保留只读兼容；新的 1.2 输出明确拒绝自由文本引用。

验收：不存在的行、列、JSON Pointer、阶段字段、错误哈希和随意后缀全部失败；最终建议可反向追踪到真实结果字段或明确假设。

### REVIEW-001 Review 严重级别决策矩阵

当前 Schema 允许 `PASS` 或 `PASS_WITH_RISKS` 同时携带 P0/P1 finding，运行时只禁止 `PASS` 携带血缘断点。

- [x] 机器执行统一矩阵：存在 P0/P1 或阻断性 required fix 时只能 `FAIL`。
- [x] `FAIL` 必须有最早合法回退阶段和非空 required fixes。
- [x] `PASS_WITH_RISKS` 只能保留非阻断风险，不能绕过必须修复项。
- [x] `PASS` 必须无血缘断点、无 required fixes、无 P0-P2 finding。
- [x] Report 必须逐项继承 `PASS_WITH_RISKS` 的 finding 和 caveat，而不是只复制顶层 risks。

验收：决策、finding 严重级别、required fixes、回退阶段和 Report caveat 之间不存在矛盾组合。

### ROUTE-001 路由输入与真实产物绑定

当前 `provided_inputs` 和阶段 `required_inputs` 是语义字符串。路由可声称已提供 `schema` 或 `query_result`，却不需要指向已注册文件和哈希。

- [x] 将输入定义改为带类型、artifact ID、路径、哈希和来源的对象。
- [x] 原始业务问题作为独立受信输入类型注册。
- [x] 路由可执行性校验必须解析每个阶段输入，不能只比较字符串集合。
- [x] 上游修订或输入文件变化时，自动使受影响路由和阶段失效。
- [x] fallback route 同样执行输入解析。

验收：没有实际 Schema、结果或数据字典时，依赖它们的阶段不能因同名字符串而启动。

### EXEC-001 查询和构建任务执行租约

查询脚本在无运行锁的情况下读取审批、访问数据库并写入固定路径，最后才由 `record_query_result` 再次加锁。期间执行 `stop`、revision 或新查询会造成过期任务继续写文件。图表和血缘构建也存在“读取状态、生成、再注册”的同类窗口。

- [x] 为查询、图表、血缘和最终渲染定义 `prepared -> executing -> publishing -> completed/aborted` 执行状态。
- [x] 在锁内签发绑定状态修订和输入哈希的 execution lease，耗时工作在锁外执行。
- [x] 发布前重新加锁并验证 lease；已停止、修订或失效的任务只能丢弃临时产物。
- [x] 支持超时、停止/修订取消和崩溃后的 lease 回收。
- [x] 增加查询与 stop/revise、重复查询、并发图表、并发血缘和 finalize/tamper 的竞态测试。

验收：过期执行既不能覆盖当前产物，也不能注册为有效证据；重试不会重复发布。

### ART-001 不可变版本产物与原子发布

当前查询结果、画像、清单、图表文件和 latest 血缘使用固定路径。新版本覆盖文件后，旧 artifact 记录被标记 superseded，审计又跳过 superseded 文件，因此历史不再可重放。

- [x] 查询结果写入 `data/queries/<query_id>/revision-<n>/`。
- [x] 图表、血缘和最终报告使用唯一版本目录或内容寻址路径。
- [x] 稳定文件名只作为可重建 pointer，不作为历史事实源。
- [x] 发布采用临时目录、完整校验、原子移动、最后更新 active pointer 的顺序。
- [x] 审计 active 和 superseded 版本；v1.2 不执行物理清理，因此当前无需生成 tombstone。

验收：任何历史审批、Review 或报告都能解析到当时的原始产物，重新运行不会覆盖旧版本。

### AUDIT-001 覆盖事件载荷的完整审计链

当前事件链只串联 `state_after` 哈希，事件类型和一般 payload 没有进入独立事件哈希；每个事件又保存完整状态快照，长修订历史会持续放大文件和校验成本。

- [x] 增加 `previous_event_sha256` 和覆盖完整规范化事件内容的 `event_sha256`。
- [x] 审计事件类型、payload、状态哈希、审批和外部产物之间的一致性。
- [x] 定义个人工作流威胁模型：默认防误改；不把普通哈希描述为防恶意重写。
- [x] 设计每 25 条事件 checkpoint 加确定性状态增量，兼容历史完整快照，并验证长历史体积、篡改与恢复。
- [x] 为 v1.1 事件提供显式迁移工具，并保留只读审计能力。

验收：修改任意历史 payload、状态、审批或产物均能被发现；长历史审计时间和文件体积有上限测试。

### FINAL-001 最终报告产物完成门禁

当前 `finalize_run` 验证 Report 阶段已完成，但不要求 `final/final-report.md` 作为独立注册产物存在；测试可使用普通 `stage.md` 完成运行。

- [x] 新增 `final_report` artifact kind 和明确 Schema/清单。
- [x] finalize 验证最终报告路径、哈希、Report stage 哈希、Review 决策和最终血缘版本。
- [x] 缺失、空白、篡改或未注册的最终报告一律阻止 `completed`。
- [x] `run-summary.json` 记录最终报告 artifact ID，而不是只列当前文件。
- [x] 增加完成后再篡改报告的 audit 测试。

验收：运行只有在真实最终报告、最终血缘和必需图表全部绑定后才能完成。

### DB-001 流式查询与执行中结果上限

当前适配器最多抓取 `max_rows + 1` 行并全部保存在内存中，CSV 和 distinct profile 也在内存构造；`max_result_bytes` 只在完整序列化之后检查。

- [x] 使用服务端或非缓冲游标分批读取 MySQL，SQLite 也采用统一迭代接口。
- [x] CSV 写入临时文件时逐行累计 UTF-8 字节数，超过审批上限立即停止并删除临时文件。
- [x] distinct、最值和画像采用有界内存算法，并明确精确或近似状态。
- [x] 查询超时覆盖连接、读取和服务端语句执行；错误清单不得泄露凭据。
- [x] 对超大单行、精确字节边界、Unicode 字节数、模拟慢读取取消和磁盘写入失败增加测试。

验收：内存使用不随批准字节上限线性失控，超限结果从未发布为有效 artifact。

### DB-002 数据源身份、TLS 与真实 MySQL 验证

当前 SQLite 指纹主要绑定路径，MySQL 指纹主要绑定 host、port 和 database；未绑定服务器身份、连接主体和 TLS 状态。真实 MySQL 集成仍未执行。

- [x] 明确“数据库身份”与“数据快照”是两个概念，并在审批资料中分别记录。
- [x] SQLite 记录规范路径与文件身份；文档明确变化数据库的一致性边界。
- [x] MySQL 记录服务器 UUID/版本、只读账号标识、TLS 模式和证书校验状态，不记录密码。
- [x] 将连接与执行 deadline 纳入执行边界并 fail closed。
- [ ] 在一次性或用户提供的真实只读 MySQL 上验证权限拒绝、超时、TLS、流式读取、Decimal、字符集和断连恢复。

验收：同名但不同物理数据库、错误主体或 TLS 降级不能复用旧查询审批；真实集成报告可重复运行。

### DATA-001 结果画像与数据质量规则

- [x] 为 `result-profile.json` 增加独立 Schema 和版本。
- [x] 正确处理混合类型、NaN/Infinity、时区、空字符串、Decimal、日期和二进制值，并输出列级质量计数。
- [x] 记录截断、抽样、近似 distinct、字段类型冲突和统计覆盖范围。
- [x] 将空结果、截断、近似统计、高空值率、样本过小等可确定告警以 artifact ID 和哈希精确传给 Review。
- [ ] 为重复主键和 cohort 成熟度增加显式主键/cohort 策略元数据；缺少定义时不得按列名猜测。
- [ ] 画像规则与指标定义、SQL 输出字段建立明确映射。

验收：画像本身可校验，Review 能区分“数据为零”“无数据”“结果被截断”和“统计为近似值”。

### VIZ-001 大结果图表渲染与精度控制

- [x] 图表读取采用流式、预聚合或显式采样，不无界加载完整 CSV。

## 7. 必测场景

| 场景 | 预期 |
|---|---|
| 调用方伪造 `user_text` | 不得获得 `trusted_host` 审批 |
| 无 Agent 回执直接 `record-stage` | 拒绝 |
| `stage_id:anything` 证据引用 | 拒绝 |
| Review `PASS` 携带 P1 finding | 拒绝 |
| 路由声明存在但未注册的 `query_result` | 不可执行 |
| 查询执行中 stop 或 revise | 结果进入 aborted，不覆盖 active artifact |
| 第二次查询同一 ID | 写入新 revision，旧 revision 仍可审计 |
| 篡改 superseded artifact 或事件 payload | audit 失败 |
| 删除 `final_report` 后 finalize | 拒绝；完成后删除则 audit 失败 |
| 单行超过 byte limit | 执行中停止，无有效结果文件 |
| MySQL 主机同名但服务器 UUID 或 TLS 状态变化 | 旧审批失效 |
| 10 万以上图表源行 | 受控聚合或采样，无无界内存增长 |
| 深层中文 Windows 路径安装 | 成功且可重复 |
| v1.1 run 升级 | 无损迁移或给出明确、可恢复的拒绝 |
